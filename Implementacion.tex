\chapter{Implementación}

En este capítulo veremos todo el proceso aplicado para implementar los diseños mostrados anteriormente. Veremos qué ha sido necesario hacer para poder construir todos los componentes que forman el sistema: el servidor back-end que hace de API, la \ac{BD}, el \ac{OS} y la interfaz de usuario.

\section{Entorno de desarrollo}

\subsection{Editor de código}

Para poder desarrollar el sistema se han utilizado dos editores de código distintos: uno para el front-end y otro para el back-end.

Para el front-end se ha decidido utilizar Visual Studio Code, ya que es uno de los editores más utilizados dentro de la industria. Además, este editor funciona de forma excelente para desarrollar aplicaciones basadas en entornos Java Script gracias a sus numerosas extensiones.

Mientras que para el back-end se ha optado por IntelliJ IDEA, un IDE de nicho cuando se trata de desarrollar sistemas implementados mediante tecnologías basadas en la JDK, como lo es en este caso Kotlin. Además, ofrece bastantes herramientas para trabajar de forma sencilla con lenguajes orientados a objetos, desarrollo de pruebas de código y ejecución y depuración de los programas desarrollados.

\subsection{Ejecución y despliegue}

El archivo \emph{docker-compose.yaml} (ver en apéndice) se ha utilizado para configurar un entorno de desarrollo aislado y reproducible. Todo ello mediante el despliegue de contenedores para la comunicación con las distintas bases de persistencia de datos.

\section{Base de datos}

Como ya hemos explicado, la \ac{BD} ha sido implementada con el motor PostgreSQL. Se ha buscado cumplir la tercera forma normal para asegurar la mantenibilidad, unicidad e integridad de los datos en todo momento.

Para implementar el modelo de datos

La \ac{BD} se ha implementado mediante los siguientes archivos .sql que dividen la creación de la \ac{BD} en cuatro pasos:

\begin{enumerate}
    \item \textbf{V1\_\_init\_schema}: crea todas las tablas necesarias para representar de forma correcta el modelo de datos.
    \item \textbf{V2\_\_add\_soft\_delete\_triggers}: crea los disparadores necesarios para poder aplicar un sistema de borrado lógico sobre los recursos cuya eliminación física acarrearía estados no deseados dentro del sistema.
    \item \textbf{V3\_\_create\_leaderboard\_view}: crea la vista encargada de calcular las puntuaciones de los equipos para cada liga, grupo y jornada.
    \item \textbf{V99\_\_insert\_initial\_data}: inserta los datos necesarios para que el sistema pueda funcionar de forma correcta: los deportes disponibles, roles de usuario y una configuración y sistema de puntuación por defecto para ligas de voleibol.
\end{enumerate}
